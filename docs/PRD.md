# PRD — Native macOS Clipboard & Snippet Manager

**Working name:** Slip
**Platform:** macOS 14+ (Sonoma), Apple Silicon + Intel
**Stack:** Swift, AppKit + SwiftUI, no third-party runtime
**Status:** Draft v1

---

## 1. Problem

Two distinct frictions, currently both handled badly by the same bad workaround:

**Repeated phrases.** Certain strings get typed dozens of times a day — "master schedule of works" being the canonical example. The current coping mechanism is abbreviating to "MoW", which degrades the output. The alternative — going somewhere else, finding the phrase, selecting it, copying it — costs more than typing it.

**Clipboard is single-slot.** macOS keeps exactly one clipboard entry. Anything copied more than one copy ago is gone. This forces constant app-switching to re-fetch things that were already in hand a minute earlier.

Existing clipboard managers solve the second problem adequately and the first one poorly: snippets are usually bolted onto a history list, buried behind the same chronological ordering, and reachable only by typing a search query. A phrase used fifty times a day should be one keystroke, not a search.

## 2. Goals

1. Retrieve any of the last N clipboard entries in under two seconds of wall-clock human time, without leaving the current app.
2. Insert a frequently-used fixed phrase into the app that currently has focus, with a single deterministic keystroke and no manual paste step.
3. Feel instant. The window is either up or it isn't; there is no perceptible loading state.
4. Never leak sensitive clipboard contents to disk.

## 2.1 The primary flow

Everything else in this document is secondary to this sequence:

1. User is working in an app — canonically a terminal.
2. User presses the global hotkey. The picker appears; the terminal does not lose focus.
3. User presses Cmd+1, or filters and presses Enter.
4. The picker disappears and the snippet text **is now in the terminal**, as though typed.

Step 4 is the product. A version of this app that leaves the text on the clipboard for the user to paste manually is not a reduced version of the product — it is a different, worse product, and not worth building, because invoke → select → Cmd+V is no cheaper than the abbreviation workaround it replaces.

This has two consequences that propagate through the rest of the document: Accessibility permission is a hard requirement rather than an enhancement, and Secure Input — which silently blocks synthetic key events and is common in exactly the terminals this targets — is a first-class engineering problem rather than an edge case.

## 3. Non-goals (v1)

- Sync across devices
- iOS companion
- Cloud storage of any kind
- Rich text / HTML fidelity preservation (plain text + images only)
- Clipboard transformations (case conversion, JSON pretty-print, etc.)
- Team/shared snippet libraries
- Inline text expansion by trigger string (`;mow` → phrase) — see Open Questions
- App Store distribution

## 4. Users

One user: the author. This is a personal tool with no onboarding budget, no settings-discovery requirements, and no need to accommodate unfamiliar mental models. Design for the power case; ignore the novice case entirely.

## 5. Core concepts

**History item** — a captured pasteboard entry. Ephemeral by nature, ordered newest-first, capped in count, subject to eviction.

**Pinned snippet** — a user-authored fixed string. Permanent, manually ordered, never evicted, always visible above history. Has a stable slot number (1–9) bound to a modifier shortcut.

These are separate tables with separate lifecycles, not one list with a flag. Keeping them separate is what allows a snippet to be one keystroke rather than a search result.

## 6. Functional requirements

### 6.1 Capture

| ID | Requirement |
|----|-------------|
| CAP-1 | Poll `NSPasteboard.general.changeCount` at 150ms. On change, read contents. |
| CAP-2 | Capture plain text (`.string`) and images (`.tiff`, `.png`). File URLs captured as text paths. |
| CAP-3 | Skip items carrying `org.nspasteboard.ConcealedType`, `TransientType`, or `AutoGeneratedType`. |
| CAP-4 | Skip items whose source application is on the user's exclusion list. |
| CAP-5 | Deduplicate: re-copying an existing item moves it to the top rather than creating a duplicate row. |
| CAP-6 | Record source application bundle ID and timestamp with each item. |
| CAP-7 | Do not capture items the app itself placed on the pasteboard during a paste operation. |

### 6.2 Storage

| ID | Requirement |
|----|-------------|
| STO-1 | Persist across app restarts and reboots. |
| STO-2 | Retain 500 history items by default; evict oldest beyond that. Configurable 100–2000. |
| STO-3 | Images stored as files on disk, keyed by content hash; database holds path + dimensions + byte size. |
| STO-4 | Reject text items over 1MB and images over 10MB. |
| STO-5 | Pinned snippets never evicted, never counted against the history cap. |
| STO-6 | All data local. No network access of any kind — the app should function identically with networking disabled. |

### 6.3 Invocation

| ID | Requirement |
|----|-------------|
| INV-1 | Global hotkey (default Cmd+Opt+V) shows the picker from any app. |
| INV-2 | Hotkey works without Accessibility permission. |
| INV-3 | Picker appears without deactivating the current frontmost application. |
| INV-4 | Escape dismisses. Click-outside dismisses. Loss of key status dismisses. |
| INV-5 | Picker appears on the display containing the mouse cursor, horizontally centred, upper third vertically. |
| INV-6 | Pressing the hotkey while the picker is open dismisses it. |

### 6.4 Selection

| ID | Requirement |
|----|-------------|
| SEL-1 | Typing filters the list. Fuzzy subsequence match against item content, case-insensitive. |
| SEL-2 | Up/Down arrows and Ctrl+N/Ctrl+P move selection. |
| SEL-3 | Enter selects. Cmd+1…Cmd+9 select the corresponding pinned snippet directly, regardless of filter state. |
| SEL-4 | Pinned snippets render above history, visually distinguished, and are excluded from filter-driven reordering. |
| SEL-5 | Each row shows content preview (2 lines max), source app icon, and relative timestamp. |
| SEL-6 | Image rows show a thumbnail. |

### 6.5 Paste — *core requirement*

| ID | Requirement |
|----|-------------|
| PST-1 | On selection: write item to `NSPasteboard.general`, hide picker, restore prior frontmost app if it changed, synthesise Cmd+V. In that order. |
| PST-2 | Text must land in the previously focused app. This is the product's primary function; a failure here is a P0 defect, not a degraded mode. |
| PST-3 | Must work in Terminal.app, iTerm2, Ghostty, Alacritty, VS Code, and standard AppKit text fields. Terminals are the primary target and are verified first. |
| PST-4 | Accessibility permission is requested during first run, with an explanation of why it is mandatory. If denied, the app shows a persistent, dismissable-per-launch banner explaining that its main function is disabled and offering a direct link to the Privacy pane. |
| PST-5 | Restore the user's previous pasteboard contents after pasting, on a short delay (~500ms), so the app doesn't clobber whatever they had copied. Configurable, on by default. |
| PST-6 | Shift+Enter pastes as plain text, stripping any attributed formatting. |
| PST-7 | Cmd+Enter copies to clipboard *without* pasting, for the cases where the user wants to place it manually. |

### 6.6 Secure Input

macOS blocks synthetic keyboard events system-wide whenever Secure Input is active. This is enabled by Terminal.app's and iTerm2's "Secure Keyboard Entry" menu option, and automatically by any focused password field anywhere on the system. Since terminals are the primary target, this will be encountered in normal use.

| ID | Requirement |
|----|-------------|
| SEC-1 | Detect Secure Input state via `IsSecureEventInputEnabled()` before attempting to paste. |
| SEC-2 | When active: write to the pasteboard, then show a brief, non-modal notice — "Secure Input active, press Cmd+V" — rather than failing silently. Silent failure is the worst possible outcome here. |
| SEC-3 | Identify the process holding Secure Input where possible, so the notice can name it. |
| SEC-4 | Document the fix (disable Secure Keyboard Entry in the terminal's menu) in the first-run flow, since the user can simply turn it off. |
| SEC-5 | Menu bar item shows a distinct state while Secure Input is active. |

### 6.7 Snippet management

| ID | Requirement |
|----|-------------|
| SNP-1 | Promote any history item to a pinned snippet from within the picker (Cmd+P on the selected row). |
| SNP-2 | Create, edit, delete, and reorder snippets in a settings window. |
| SNP-3 | Snippets have an optional short label shown in place of content when content is long. |
| SNP-4 | Slot assignment (1–9) is explicit and reorderable, not derived from list position. |

### 6.8 Privacy controls

| ID | Requirement |
|----|-------------|
| PRV-1 | Application exclusion list — any app can be added; nothing copied while it is frontmost is captured. Password managers pre-populated. |
| PRV-2 | Global pause toggle from the menu bar, with an optional auto-resume timer. |
| PRV-3 | Delete individual item (Cmd+Delete in picker). |
| PRV-4 | Clear all history, with confirmation. |
| PRV-5 | Optional: skip any captured string matching common secret patterns (long base64, `sk-` prefixed keys, JWTs). Off by default. |

### 6.9 Chrome

| ID | Requirement |
|----|-------------|
| CHR-1 | No Dock icon (`LSUIElement`). Menu bar item is the only persistent UI. |
| CHR-2 | Menu bar: pause toggle, open settings, quit. |
| CHR-3 | Launch at login toggle. |
| CHR-4 | Hotkey is user-configurable via a recorder control. |

## 7. Performance budgets

These are requirements, not aspirations. A miss here is a bug.

| Metric | Budget |
|--------|--------|
| Hotkey press → window visible with content rendered | < 50ms |
| Keystroke → filtered list updated | < 16ms (one frame) |
| Enter → clipboard written | < 10ms |
| Enter → paste landed in target app | < 150ms |
| Idle CPU | < 0.1% |
| Idle memory | < 60MB |
| Cold launch to monitoring | < 500ms |

Implication: the window and its view hierarchy are constructed once at launch and hidden, never built on demand. Filtering runs against an in-memory array, not the database.

## 8. Permissions

| Permission | Required for | If denied |
|-----------|--------------|-----------|
| Accessibility | Synthesised Cmd+V — the primary function | App's core purpose is unavailable. Persistent banner, direct link to the Privacy pane. |
| None | Capture, hotkey, picker, clipboard write | — |

This is a personal tool on the author's own machine, so the permission is granted once and never thought about again. Requested during first run rather than lazily on first paste — deferring it only produces a confusing first failure.

The app should still not *crash* or become unusable without it; history browsing and clipboard-setting continue to work. But this is a broken state to be surfaced loudly, not a supported configuration.

## 9. Success criteria

Judged after two weeks of daily use:

1. Hotkey → Cmd+1 → the phrase is in the terminal. Every time, without thinking about it. This is the criterion; the rest are secondary.
2. "MoW" no longer appears in written output — the full phrase is used because it is now cheaper than the abbreviation.
3. Zero instances of switching to another app purely to re-copy something.
4. No perceptible hesitation between hotkey and window. If the window is ever *watched* appearing, it has failed.
5. Zero instances of a password or token appearing in history.
6. Zero instances of a paste silently doing nothing — Secure Input cases are always explained.

## 10. Open questions

1. **Inline expansion.** Typing `;mow` and having it expand in place is strictly faster than any picker for the single most common case. It also requires an event tap, full Accessibility permission, and a per-keystroke state machine — significantly more surface area and risk. Deferred to v2, but the snippet data model should not preclude it (hence SNP-4's explicit trigger-capable slot design). macOS built-in Text Replacement is the stopgap.
2. **Fuzzy vs. prefix matching.** Fuzzy is more forgiving; prefix is more predictable. Predictability may matter more when muscle memory is the goal. Start fuzzy, evaluate.
3. **Item count.** 500 is a guess. Instrument actual scroll depth and revise.
4. **Fork vs. build.** Maccy (MIT, Swift) already implements polling, hotkey registration, and panel management. Forking it and building the snippet layer is plausibly a one-evening path to the actual goal. Building from scratch is the right call only if learning the platform is itself a goal. This decision precedes everything in the implementation plan.
